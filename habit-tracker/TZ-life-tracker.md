# ТЗ: приложение для управления направлениями жизни

Версия для реализации. Компоновка выбрана — «Рабочий стол», три зоны.
Референс-прототип: `desktop-v2.html` (кликабельный, вся логика расчётов внутри).

---

## 1. Что строим

Desktop-приложение. Главный экран отвечает на один вопрос: **что мне нужно сделать сегодня**, и вторым слоем — что накатывает до конца недели и как держатся привычки.

Логика данных: **Направление → Цель → Задачи + Привычки**.

Единого показателя «моя жизнь — X%» нет и не должно появиться. Процент имеет смысл только внутри направления.

---

## 2. Стек

Свободный выбор, но по умолчанию:

- React 18 + TypeScript + Vite
- Хранение: SQLite локально (better-sqlite3 / Tauri SQL plugin). Для первой итерации допустим IndexedDB, но схему сразу проектировать реляционно
- Оболочка: Tauri (легче Electron), либо чистый web-билд на первом этапе
- Стили: CSS-переменные, без UI-китов. Дизайн-токены — из прототипа

Первая итерация может быть web-only, без десктоп-оболочки. Мобильную версию не делаем.

---

## 3. Модель данных

```
Direction
  id, name, order, archived: bool

Goal
  id, directionId, name, type: 'achievement' | 'maintenance',
  order, status: 'active' | 'done' | 'archived', createdAt

Task
  id, goalId, title, dueDate: date | null, doneAt: datetime | null,
  createdAt, order

Habit
  id, goalId, directionId, name,
  schedule: { type: 'daily' } | { type: 'weekly', timesPerWeek: number }
           | { type: 'weekdays', days: number[] },
  archived: bool, createdAt

HabitEntry
  id, habitId, date: date, done: bool
```

Правила целостности:

- Задача всегда принадлежит цели (п. 4 исходного ТЗ). См. открытый вопрос 12.1
- Привычка принадлежит цели, но `directionId` дублируется явно: при закрытии цели привычка не удаляется, а переносится или продолжает жить в направлении
- `HabitEntry` создаётся только для прошедших дней и сегодня. Записи на будущее запрещены на уровне слоя данных
- Архивирование вместо удаления везде, кроме явного «удалить навсегда»

**Два типа целей — обязательно.** `achievement` («Набрать 5 кг») имеет финиш, процент растёт к 100 и цель закрывается. `maintenance` («Нормализовать режим сна») финиша не имеет, у неё показывается не прогресс, а удержание за 30 дней. Если типы не развести, половина целей навсегда зависнет на 40% и цифры перестанут значить что-либо.

## 4. Расчёт прогресса

```
adherence(habit, N дней) = выполненных дней / запланированных дней за окно N

goalProgress(goal):
  if type == 'achievement':
      tasksPart = закрытых задач / всего задач
      habitsPart = среднее adherence(h, 30) по привычкам цели
      = tasksPart * 0.7 + habitsPart * 0.3          (если привычек нет — 100% задачи)
  if type == 'maintenance':
      = среднее adherence(h, 30) по привычкам цели

directionProgress(direction) = среднее goalProgress по активным целям

dayCompletion(date) = (закрытых задач дня + выполненных привычек дня)
                    / (всего задач дня + всего привычек дня)

weekCompletion = среднее dayCompletion по прошедшим дням недели
```

Известная проблема, которую нужно проверить на реальных данных: у долгих целей с 15+ задачами процент почти не двигается — одна закрытая задача даёт +5%. Если это подтвердится, переключить `tasksPart` на скользящее окно 30 дней (закрыто за 30 дней / (закрыто + просрочено + запланировано на период)). Формулу вынести в отдельный модуль `progress.ts`, чтобы менять в одном месте.

Серия привычки: количество подряд выполненных **запланированных** дней, считая от сегодня назад. Незапланированный день (например, суббота у привычки «по будням») серию не рвёт и не продлевает.

## 5. Экран: раскладка

Три колонки, grid `230px | 1fr | 336px`, высота — весь вьюпорт.

### 5.1 Левая рейка — навигация

- Первый пункт: **Сегодня**, выбран при запуске. Справа — счётчик незакрытых задач на сегодня
- Ниже: список направлений, у каждого название, процент, полоса прогресса
- Клик по направлению переключает центральную колонку в режим направления
- Внизу «+ направление»
- Рейка прокручивается независимо

### 5.2 Центр, режим «Сегодня»

1. Заголовок: дата прописью, справа «осталось N»
2. Тонкая линия недели: 7 сегментов, толщина/заливка = `dayCompletion`, сегодняшний выделен. Ретроспектива, читается боковым зрением
3. **Список задач на сегодня, крупно** (18–19px, строки по 17px вертикального паддинга). Чекбокс, название, чип направления, время дедлайна
4. Выполненные уходят из списка, под ним строка «Сделано: N · показать»
5. Пустое состояние: «На сегодня всё» + ближайшая задача
6. Блок **«Осталось на этой неделе»**: 6 колонок (завтра → воскресенье). В каждой — день, счётчик, до трёх названий задач, «+N» при переполнении. Колонка с 3+ задачами подсвечивается рамкой

### 5.3 Центр, режим направления

Заголовок — название направления. Ниже цели карточками: название, процент, полоса, привычки цели, свёрнутый блок «Задачи — N ›», раскрывающийся по клику. Внутри — задачи с чекбоксами и датами, кнопка добавления задачи.

### 5.4 Правая колонка — привычки

Отдельный блок, не смешивается с задачами.

- Для каждой привычки: название, справа название направления (в режиме «Сегодня»)
- Ряд из 7 ячеек: **3 дня до сегодня, сегодня, 3 дня после**
- Прошедшие дни: выполнено — заливка + галочка, пропущено — тонкая рамка и ✕. Кликабельны, это окно доотметки
- Сегодня: рамка толще, кликабельна
- Будущие: пунктирная рамка, некликабельны, только план
- Справа от ряда — **серия крупной цифрой** и подпись «дней»
- В шапке блока — счётчик «N / M сегодня»

Ограничение: 7 ячеек + серия занимают 336px впритык. При 7+ привычках колонка уйдёт в прокрутку. Если это произойдёт — сжимать окно до −2/+1, а не уменьшать ячейки.

## 6. Взаимодействия

| Действие | Что пересчитывается немедленно |
|---|---|
| Чекбокс задачи | «осталось N», сегмент недели, процент цели и направления, счётчик в рейке |
| Клик по ячейке привычки | серия, `adherence`, процент цели и направления, сегмент дня |
| Доотметка прошлого дня | то же + серия может вырасти скачком |
| Переключение направления в рейке | центр целиком |

Всё локально и синхронно, без спиннеров. Анимации — только заливка полос и галочки, 150–500 мс, с уважением к `prefers-reduced-motion`.

---

## 7. Создание и ввод

Без этого приложение опустеет за три недели.

- Быстрое добавление задачи: `Cmd/Ctrl + N` из любого места, поле «что сделать», выбор цели, дата
- Добавление привычки — из карточки цели
- Добавление цели — из режима направления, с обязательным выбором типа
- Массовый перенос просроченных: при запуске, если есть задачи с датой в прошлом и незакрытые, показать полосу «Просрочено: N — перенести на сегодня / разобрать»

---

## 8. Клавиатура

- `↑ ↓` — навигация по списку сегодня
- `Space` — отметить/снять
- `Cmd/Ctrl + N` — новая задача
- `1…9` — переключение направлений в рейке
- `Esc` — закрыть модалку/сбросить фокус

## 10. Что НЕ делаем в первой версии

- Мобильную версию и синхронизацию
- Общий процент «жизни»
- Уведомления и напоминания
- Подзадачи, теги, приоритеты
- Графики и статистику глубже 30 дней
- Мультипользовательский режим

---

## 11. Критерии готовности

1. Создаю направление, цель, три задачи и привычку — всё сохраняется между перезапусками
2. Отмечаю задачу на сегодня — процент цели, направления и сегмент дня меняются мгновенно
3. Доотмечаю привычку за позавчера — серия пересчитывается корректно, будущие дни отметить невозможно
4. Закрываю все задачи дня — центр показывает пустое состояние, блок недели остаётся заполненным
5. Восемь направлений — рейка прокручивается, раскладка не ломается
6. Цель типа `maintenance` не показывает процент выполнения задач, а показывает удержание

## 12. Решения, которые нужно принять до кода

**12.1 Задачи без цели.** Исходное ТЗ требует обязательной привязки. На практике «забрать посылку», «продлить страховку» не относятся ни к одной цели — либо появится помойная цель «Разное», либо ввод уедет обратно в заметки. Вариант: инбокс — задача создаётся без `goalId`, попадает в «Сегодня», в проценты не входит, привязывается позже или никогда. **Решить до создания схемы БД: `goalId` nullable или нет.**

**12.2 Отметка вне компьютера.** Тренировку отмечают в зале, звонок родителям — с дивана. При desktop-only отметки будут задним числом, а серии покажут дисциплину заполнения, а не жизнь. Окно доотметки на 3 дня частично лечит, но если приложение приживётся — понадобится способ отметить с телефона. Схему данных проектировать так, чтобы позже прикрутить синхронизацию (уникальные id, timestamps, никаких автоинкрементов как единственного ключа).

**12.3 Ретроспектива недели.** Сейчас на главном экране одновременно линия «как прошла неделя» (назад) и блок «осталось» (вперёд). Линия почти не читается. Возможно, ретроспективу стоит убрать на отдельный экран, а на главном оставить только «вперёд».

**12.4 Что попадает в «Сегодня».** Только задачи с сегодняшним дедлайном — или ещё просроченные? От этого зависит, будет список из 4 строк или из 15.
