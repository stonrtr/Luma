# ТЗ — «Приоритеты» (личная канбан-доска целей)

## 1. Назначение

Личный (однопользовательский) инструмент для приоритизации целей по сферам жизни (здоровье, финансы, обучение, спорт, карьера и т. д.) и отслеживания задач по ним на доске в стиле канбан. Без учёток, без multi-user — рассчитан на одного человека, себя.

## 2. Стек

- **Backend:** Python 3 + Flask, без ORM (сырой SQL через `sqlite3`).
- **БД:** SQLite, файл `server/board.db`, миграции — самописные, идемпотентные, выполняются при каждом старте (`init_db()` в `server/db.py`).
- **Frontend:** без сборки и фреймворков — чистый HTML/CSS/JS (`client/index.html`, `client/static/app.js`, `client/static/style.css`). Рендер полностью через `render()`, перерисовывающий DOM с нуля при любом изменении состояния.
- **Порт:** 5051 (переопределяется через `PORT`).
- **Аутентификация:** отсутствует.

## 4. Функциональность

### 4.1 Доска
- Сетка: строки — Сегодня / Неделя / Месяц / Без срока (фиксированный порядок, общие для всех столбцов); столбцы — направления.
- **Порядок столбцов автоматический по срочности**: первыми идут направления, у которых есть задача «на сегодня»; далее (среди оставшихся) — у кого есть на неделю; затем месяц; затем без срока; затем те, где вообще нет задач. Внутри одной группы срочности порядок — ручной (см. ниже).
- Пустая ячейка (нет задач) рендерится без фона/рамки/отступов — просто пустое место, не «пустая коробка». Ячейка с задачами получает обычный вид (белая карточка-подложка).
- Карточка задачи: чекбокс (единственный статус — сделано/не сделано), текст (редактируется по клику, сохраняется по blur/Enter), крестик-удаление (скрыт, появляется по hover — progressive disclosure).
- Drag-and-drop карточки между любыми ячейками (смена направления и/или срока).
- Drag-and-drop заголовков направлений — перетаскивание одного на другой **меняет их местами** (swap `sort_order`), это и есть «ручной» порядок, о котором выше.
- Клик по заголовку направления открывает Настройки, сразу проскроллив к этому направлению.

### 4.2 Выполненные задачи и архивация
- Выполненная задача пропадает из своей ячейки и в течение 7 дней с момента отметки показывается в общем блоке **«Выполнено за неделю»** под доской (обратный отсчёт по `done_at`).
- Через 7 дней задача перестаёт приходить с `/api/board` и видна только в архиве.
- Из трея можно вернуть задачу в работу (снять галочку) или удалить навсегда.

### 4.3 Направления (векторы) — управляются только в Настройках
Настройки открываются иконкой ⚙️ в шапке. На каждое направление:
- обложка (фон-фото): загрузка/замена/удаление;
- название — поле ввода прямо на обложке (рядом же, где загрузка фона);
- эмодзи — выбор из палитры-попапа (≈60 иконок по темам: здоровье/спорт/финансы/учёба/работа/творчество), а не свободный ввод;
- список целей: чекбокс «достигнута» на каждой, текстовое поле, удаление, кнопка «Добавить цель» — целей можно несколько;
- кнопка «В архив» (мягкое удаление, не безвозвратное);
- внизу списка — «Добавить направление» и ссылка «Архив».

На доске в шапке направления показываются **только недостигнутые** цели (список строк с 🎯), достигнутые скрываются (но остаются видны и снимаемы в Настройках).

### 4.4 Архив
Отдельный экран (открывается из Настроек или из трея «Выполнено за неделю»):
- **Направления в архиве** — восстановить или удалить навсегда (полное удаление каскадно стирает его задачи и цели).
- **Все выполненные задачи** (не только за последнюю неделю) — вернуть в работу или удалить навсегда.

### 4.5 Добавление задачи
Большая круглая кнопка "+" внизу слева (фиксированная, поверх контента) открывает модалку: выбор направления, сегмент-контрол срока (Сегодня/Неделя/Месяц/Без срока), поле текста. После добавления модалка не закрывается, а очищает поле — можно быстро закинуть несколько задач подряд.

## 5. API

| Метод | Путь | Действие |
|---|---|---|
| GET | `/api/board` | направления (не в архиве) + активные задачи (не выполненные ИЛИ выполненные < 7 дней назад) + цели |
| GET | `/api/archive` | направления в архиве + все выполненные задачи |
| POST | `/api/categories` | создать направление |
| PATCH | `/api/categories/<id>` | изменить name/emoji/background_image/sort_order |
| DELETE | `/api/categories/<id>` | архивировать (мягко) |
| POST | `/api/categories/<id>/restore` | вернуть из архива |
| DELETE | `/api/categories/<id>/purge` | удалить навсегда (каскадно) |
| POST | `/api/categories/<id>/goals` | добавить цель |
| PATCH | `/api/goals/<id>` | изменить текст/done |
| DELETE | `/api/goals/<id>` | удалить цель (безвозвратно) |
| POST | `/api/cards` | создать задачу |
| PATCH | `/api/cards/<id>` | изменить title/done/timeframe/category_id (перенос между ячейками пересчитывает `sort_order`) |
| DELETE | `/api/cards/<id>` | удалить задачу (безвозвратно) |

Тело запросов/ответов — JSON. Ограничение на размер запроса — 8 МБ (из-за загрузки фото как data URL).

## 6. UI/UX-принципы, которых придерживались

- **iOS-подобный визуальный язык**: системные цвета/шрифт (-apple-system), скруглённые карточки, размытая навигационная панель, попапы в стиле actionsheet.
- Светлая тема (принудительно, без авто-переключения по системной теме).
- **Progressive disclosure**: второстепенные/разрушительные действия (удаление) скрыты до наведения; управление направлениями убрано с доски в отдельный экран настроек.
- **Jakob's Law**: drag-and-drop карточек и заголовков — привычный паттерн, знакомый по Trello/Asana.
- **Minimalist design (Nielsen)**: пустые ячейки не рисуют лишних рамок и не занимают внимание.

## 7. Известные ограничения / что сознательно не сделано

- **Нет повторяемости/привычек.** Из первоначального замысла — «на сегодня» должны быть привычки и регулярные мини-задачи — сейчас каждая задача одноразовая: выполнил → ушла в архив, сама не возвращается. Требует отдельного поля повторения и логики пересоздания.
- **Цели и задачи не связаны.** Можно завести цель и десяток задач в том же направлении, но явной связи «эта задача — шаг к этой цели» нет.
- Нет заметок/подзадач/дедлайнов с конкретной датой — только грубые корзины «сегодня/неделя/месяц/без срока».
- Нет поиска и фильтрации по всей доске.
- Нет статистики/прогресса (сколько целей достигнуто за период и т. п.).
- Нет бэкапа/экспорта данных — всё в одном файле `board.db`.
- Нет отмены (undo) для безвозвратных удалений (только подтверждение через `confirm()`).
- Не проверялось на мобильных экранах/тач-драге — вёрстка адаптивная, но drag-and-drop рассчитан на мышь.

