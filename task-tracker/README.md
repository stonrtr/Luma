# task-tracker — упрощённый клон Worksection

Личная канбан-доска для каждого члена небольшой команды: статусы «Ідея / Зробити / В роботі /
Погодити / Зроблено / На паузі», дедлайны, приоритет по 10-балльной шкале, повторяющиеся задачи,
комментарии, обзор эффективности. Без биллинга и без тайм-трекинга.

## Стек

- **Next.js 16** (App Router, TypeScript) — один full-stack проект, без отдельного backend-сервиса
- **Prisma + SQLite** (файл `prisma/dev.db` локально, создаётся автоматически при первой миграции)
- **Auth.js (NextAuth v5)** — вход по email/паролю, JWT-сессии, роли `ADMIN`/`MEMBER`
- **Tailwind CSS + shadcn/ui**, **dnd-kit** (drag-and-drop канбана), **Zod** (валидация)

## Настройка перед первым запуском

### 1. Node.js

Нужен Node.js 20.9+ (см. `package.json`). Если не установлен — проще всего через
[nvm](https://github.com/nvm-sh/nvm):

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
nvm install 22
```

### 2. Установить зависимости

```bash
cd task-tracker
npm install
```

### 3. Переменные окружения

Создать `task-tracker/.env`:

```
DATABASE_URL="file:./dev.db"
AUTH_SECRET="<случайная строка>"

ADMIN_NAME="Имя Фамилия"
ADMIN_EMAIL="admin@example.com"
ADMIN_PASSWORD="Пароль1!"
```

`AUTH_SECRET` — сгенерировать командой:

```bash
openssl rand -base64 32
```

### 4. Применить миграции и создать первого администратора

```bash
npx prisma migrate deploy   # (или `migrate dev` при первом локальном запуске)
npx prisma db seed
```

Скрипт `prisma/seed.ts` идемпотентен — читает `ADMIN_NAME`/`ADMIN_EMAIL`/`ADMIN_PASSWORD` из
окружения и создаёт (или обновляет) единственного администратора. Никакого отдельного
`bootstrap_admin.py`, как в других проектах этого репозитория, не требуется.

### 5. Запустить сервер

```bash
npm run dev
```

Открыть [http://localhost:3000](http://localhost:3000) и войти под данными из `.env`.

## Модель ролей и доступов

- **Администратор** (`ADMIN`) — единственный способ получить эту роль — быть созданным через
  `prisma/seed.ts`. Раздел «Команда» (`/admin/users`) — создаёт остальных участников (имя, email,
  временный пароль; письмо не отправляется, пароль передаётся лично) и открывает **доску любого
  участника** на просмотр и редактирование (`/team/[userId]`).
- **Участник** (`MEMBER`) — видит и редактирует только свою личную доску (`/`). Чужие доски и
  раздел «Команда» ему недоступны — это проверяется и в `src/proxy.ts` (оптимистичная проверка по
  JWT), и на самих страницах через `requireAdmin()`.
- У каждого пользователя — ровно одна личная доска (задачи, где он указан «Ответственным»).
  Отдельного понятия «проект» в этой версии нет — это сознательное упрощение, по аналогии с
  моделью существующего в этом репозитории Flask-трекера `server/`.

## Как пользоваться

Доска (`/` — своя, `/team/[userId]` — чужая для админа) открывается вкладками сверху:

1. **Огляд** — три показателя (создано задач / выполнено / выполнено в срок) и столбчатая
   диаграмма открытых задач по статусам.
2. **Канбан** — 6 цветных колонок-статусов, пустые сворачиваются в узкую полосу. Кнопка «+» в
   шапке каждой колонки создаёт задачу сразу в ней, кнопка «+ Задача» у заголовка доски — без
   привязки к колонке. Переключатель «Открытые / Закрытые / Все» фильтрует по статусу «Зроблено»,
   сортировка — по порядку/названию/сроку. Карточка: чекбокс слева (для выбора нескольких задач и
   массового закрытия кнопкой «Закрыть»), приоритет справа от названия (число 1–10, цвет от
   зелёного к красному), дедлайн и аватар снизу. Вся карточка целиком — и ссылка на открытие
   задачи, и ручка для drag-and-drop между колонками.
3. **По дням** — группировка по срокам: «Ідеї / Прострочені / На сьогодні / На завтра /
   На тиждень / На місяць».
4. **Календарь** — рабочая неделя (пн–пт) с задачами по датам дедлайна и навигацией по неделям.
5. **Регулярные** — шаблоны повторяющихся задач (ежедневно / по дню недели / по числу месяца).
   Когда наступает срок, задача автоматически создаётся в колонке «Зробити» — проверка происходит
   при каждом заходе на доску (без отдельного cron-процесса).

Клик по названию задачи открывает деталку: редактирование
названия/описания/статуса/приоритета/срока/ответственного и лента комментариев.

Аватар в шапке (клик открывает `/settings`) — редактируемое фото профиля (загружается файлом,
хранится как data URL в БД); пока фото не загружено, показывается сгенерированная по имени
картинка-заглушка.

## Деплой на Render.com

Сервис для `task-tracker` уже добавлен в корневой `render.yaml` (второй `services:` элемент,
рядом с существующим `top-superfoods-tracker`). Render развернёт web-сервис с постоянным диском
для SQLite — тот же паттерн, что и у остальных проектов в этом репозитории.

1. Запушить репозиторий на GitHub (если ещё не сделано) и подключить его в Render — **New +  →
   Blueprint**.
2. Render подхватит оба сервиса из `render.yaml`. Заполнить переменные окружения для
   `task-tracker` в его карточке: `AUTH_SECRET`, `ADMIN_NAME`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`.
3. После первого деплоя один раз выполнить сид администратора через Render Shell (вкладка Shell
   у сервиса):
   ```bash
   npx prisma db seed
   ```
4. Открыть выданный Render-адрес и войти под созданным админом.

Дальнейшие обновления — обычный `git push`, Render передеплоит автоматически (build command уже
включает `prisma migrate deploy`).

## Данные и секреты

- `prisma/dev.db` (локально) / диск на Render (в проде) — SQLite-база со всеми
  пользователями/задачами/комментариями. Не коммитится (см. `.gitignore`).
- `.env` — `DATABASE_URL`, `AUTH_SECRET`, `ADMIN_*` — создаётся вручную, не публикуется.
- Загруженные аватары хранятся прямо в колонке `User.avatarUrl` как `data:` URL (до 1 МБ на файл)
  — отдельного файлового хранилища/S3 не требуется, но для сотен пользователей с фото это не
  масштабируется; для такого случая стоит вынести в объектное хранилище.
- Сбросить локальную базу и накатить миграции заново: `npx prisma migrate reset`.

## Чего сознательно нет в этой версии

- Полностью кастомные (переименовываемые/создаваемые) колонки на доску — статусы фиксированы в
  коде.
- Метки/теги задач, файлы-вложения к задачам, подписчики и гибкая видимость задачи для отдельных
  людей.
- Rich-text редактор описания (сейчас обычный `textarea`).
- График активности по дням (как в референсе Worksection) — нужен отдельный журнал событий,
  которого пока нет.
