# top superfoods — таск-трекер

Личный Kanban + календар для кожного члена команди, з ієрархією "адмін бачить підлеглих".

## Стек

- Backend: Python + Flask + SQLite (файл `server/tracker.db`, создаётся автоматически)
- Frontend: обычные HTML/CSS/JS без сборки, раздаются тем же Flask-сервером
- Письма-приглашения отправляются через SMTP (`smtplib`, без сторонних библиотек)

## Настройка перед первым запуском

### 1. Установить зависимости

```bash
cd server
python3 -m pip install -r requirements.txt
```

### 2. Настроить отправку писем (SMTP)

Создать файл `server/.env` со своими данными почтового провайдера:

```
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=you@topsuperfoods.com
SMTP_PASSWORD=пароль_приложения
SMTP_FROM=you@topsuperfoods.com
```

Без этого файла отправка приглашений будет падать с ошибкой «SMTP не налаштовано».

### 3. Подключить Google Calendar (двусторонняя синхронизация, опционально)

Каждый пользователь может подключить свой личный Google Calendar кнопкой «📅 Google Calendar»
в шапке — задачи с указанным «Час початку» будут автоматически создаваться/обновляться/удаляться
как события в его календаре, а при выборе даты в форме задачи сбоку появляется реальная занятость
из Google Calendar на этот день.

Чтобы это заработало, один раз нужно создать OAuth-приложение в Google Cloud Console:

1. [console.cloud.google.com](https://console.cloud.google.com/) → создать проект.
2. **APIs & Services → Library** → найти **Google Calendar API** → **Enable**.
3. **APIs & Services → OAuth consent screen** → User Type **External** → название приложения,
   добавить свою почту как test user (если приложение в режиме Testing) → в Scopes добавить
   `.../auth/calendar`.
4. **APIs & Services → Credentials → Create Credentials → OAuth client ID** → тип **Web application**.
5. В **Authorized redirect URIs** указать: `http://localhost:5050/api/google/callback`
   (и то же самое с адресом в локальной сети, если открываете трекер по IP).
6. Скопировать **Client ID** и **Client Secret** в `server/.env`:

```
GOOGLE_CLIENT_ID=xxxxxxxxxx.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=xxxxxxxxxx
GOOGLE_REDIRECT_URI=http://localhost:5050/api/google/callback
```

Без этих переменных кнопка подключения покажет понятную ошибку, а весь остальной функционал
трекера (в том числе внутренняя занятость по задачам/дзвінкам) продолжит работать как обычно.

### 4. Создать первого администратора

Регистрации через форму нет — единственный способ завести самый первый (админский) аккаунт:

```bash
cd server
python3 bootstrap_admin.py "Ім'я Прізвище" admin@topsuperfoods.com "Пароль1!"
```

Пароль должен быть 8+ символов, минимум 1 заглавная буква и 1 спецсимвол.

### 5. Запустить сервер

```bash
python3 app.py
```

Открыть http://localhost:5050 и войти под созданным админом.

## Модель ролей

- **Администратор** — создаётся только через `bootstrap_admin.py`, либо любой пользователь,
  которого он пригласил, если сам является админом (в текущей версии приглашённые всегда
  становятся обычными участниками — сделать кого-то ещё админом можно только вручную в БД,
  полем `users.is_admin`).
- **Обычный участник** — видит и редактирует только свою личную доску/календарь.
- Тот, кто пригласил пользователя, становится его "керівником" (`manager_id`) и получает доступ
  на просмотр/редактирование доски и календаря этого пользователя через переключатель команды
  в шапке. Обычные участники чужие доски не видят.

## Как пользоваться

1. После входа сразу открывается личная Kanban-доска с 4 колонками: **Ідеї / До виконання / У процесі / Виконано**.
2. Задачи создаются кнопкой «+ Нове завдання»: назва, опис, статус, термін виконання.
3. Карточки перетаскиваются между колонками (drag-and-drop).
4. Завдання зі статусом «Виконано» автоматично зникають з дошки через **7 днів** і потрапляють
   в прихований архів — відкривається кліком на кнопку «Архів (n)»; звідти їх можна відновити.
5. Перемикач «Канбан / Календар» у шапці показує тижневий календар (пн–нд) з термінами завдань
   та запланованими дзвінками; дзвінки додаються кнопкою «+ Дзвінок» (назва, дата, час початку/кінця).
6. Адміністратор кнопкою «+ Запросити» вводить ім'я та email нового учасника:
   - если у человека уже есть аккаунт — придёт ошибка "уже существует" (повторно пригласить нельзя);
   - если аккаунта нет — ему на почту уходит письмо со ссылкой для создания пароля.
7. Новый участник переходит по ссылке из письма, придумывает пароль (8+ символов, 1 заглавная,
   1 спецсимвол) — и сразу попадает в свою личную (пустую) доску, а пригласивший его админ
   получает доступ на просмотр его доски/календаря через переключатель команды в шапці.

## Запуск для всей команды

Локально сервер слушает на `0.0.0.0:5050`, то есть доступен по IP машины, на которой запущен
(например `http://192.168.x.x:5050`), всем в локальной сети — ссылки в письмах-приглашениях
строятся автоматически по адресу, с которого пришёл запрос. Для доступа из интернета и для
Google OAuth (требует HTTPS) — деплой на Render, см. ниже.

## Деплой на Render.com

В репозитории уже есть `render.yaml` — Render разворачивает web-сервис и постоянный диск
для SQLite одной кнопкой.

1. **Создать репозиторий на GitHub** и запушить туда этот проект:
   ```bash
   git remote add origin https://github.com/<ваш-аккаунт>/<репозиторий>.git
   git push -u origin main
   ```
2. Зарегистрироваться на [render.com](https://render.com/) (можно через GitHub-аккаунт).
3. **New + → Blueprint** → выбрать репозиторий → Render подхватит `render.yaml` и покажет
   форму со всеми переменными окружения (`SMTP_*`, `GOOGLE_*`, `BOOTSTRAP_SECRET`) — их можно
   заполнить сразу или позже во вкладке **Environment** созданного сервиса.
   - `BOOTSTRAP_SECRET` — придумайте любой случайный пароль, он понадобится один раз для
     создания первого администратора.
4. Нажать **Apply** — Render соберёт и задеплоит сервис, выдаст адрес вида
   `https://top-superfoods-tracker.onrender.com`.
5. **Обновить Google OAuth redirect URI**: в Google Cloud Console → Credentials → ваш OAuth
   Client → Authorized redirect URIs — добавить
   `https://top-superfoods-tracker.onrender.com/api/google/callback`, и это же значение
   прописать в переменной окружения `GOOGLE_REDIRECT_URI` на Render.
6. **Создать первого администратора** (без shell-доступа это делается через API):
   ```bash
   curl -X POST https://top-superfoods-tracker.onrender.com/api/setup/bootstrap-admin \
     -H "Content-Type: application/json" \
     -d '{"secret":"<ваш BOOTSTRAP_SECRET>","name":"Ім'"'"'я Прізвище","email":"admin@topsuperfoods.com","password":"Пароль1!"}'
   ```
   Эндпоинт работает только один раз (пока в базе нет ни одного администратора) — второй вызов
   вернёт ошибку «Адміністратор вже існує».
7. Открыть выданный Render-адрес в браузере и войти под созданным админом.

После первого деплоя дальнейшие обновления — это просто `git push` в подключённую ветку,
Render передеплоит автоматически.

## Данные и секреты

- `server/tracker.db` — база данных SQLite со всеми пользователями/задачами/дзвінками/приглашениями
  и OAuth-токенами подключённых Google-аккаунтов.
- `server/secret.key` — секрет для подписи JWT-токенов, создаётся автоматически при первом запуске.
- `server/.env` — SMTP- и Google OAuth-данные (создаётся вручную, не публикуется).
